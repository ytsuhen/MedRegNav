# Хендоф: MedReg Navigator, продовження з M5 у Claude Code

Робочий документ для передачі між сесіями (21.10.2026). Після M6 його можна видалити.

## 0. Перший крок

```sh
git clone https://github.com/ytsuhen/MedRegNav && cd MedRegNav
corepack enable && pnpm i
pnpm verify        # tsc, Biome, 137 тестів — має бути зеленим
pnpm mrn check     # джерела, цитати, правила, приклади, обов'язки, подання, what-if — усе ok
```

Перед роботою прочитай `CLAUDE.md` (незмінні правила, команди, пастки), `docs/SPEC.md` (обсяг і етапи),
`docs/DECISIONS.md` (усі рішення й розбіжності з брифом: D1–D8, L1–L5, A1–A3, I1–I10, O1–O5, U1–U10),
`docs/ARCHITECTURE.md` (модулі й формати даних).

## 1. Що це

Демо для портфоліо (не продукт): користувач описує медичне ПЗ атрибутами й бачить, чи це медвиріб у ЄС, його клас за
MDR (додаток VIII, правило 11 + правила застосування 3.3 і 3.5), що з цього випливає за AI Act і які обов'язки,
документи й стандарти потрібні. Кожна відповідь простежується до дослівної цитати офіційного тексту (sha256 секції +
зсуви + quote; тест перевіряє кожну). Рушій — тризначна логіка (невідоме = null), результат — множина можливих
виходів; веб-застосунок статичний, рушій працює в браузері.

## 2. Незмінні правила (з брифу, дослівно)

- «Жодного коду, що знає конкретне правило чи статтю: правила, атрибути, обов'язки й стандарти — дані в `data/`.»
- «Кожен вузол правила і кожен обов'язок мають хоча б одну цитату з дослівного джерела (крім структурних вузлів-«клею»).»
- «Правила читають лише атрибути з реєстру `data/attributes.json`.»
- «Результат завжди позначений як підтримка рішення, а не рішення. Усі правила мають статус `draft`.»
- «Жодних матеріалів, назв чи кодових назв мого роботодавця. Назв комерційних рушіїв правил не згадувати.»
- «Якщо цей бриф суперечить дослівному тексту закону, перемагає текст закону. Розбіжність записати в `docs/DECISIONS.md`.»
- «Якщо мережа не пускає до EUR-Lex чи сайту Єврокомісії, зупинись і попроси мене завантажити файли в
  `data/sources/inbox/`. Ніколи не переказуй і не відновлюй юридичний текст з пам'яті.»
- «Якщо чогось бракує (доступ до репозиторію, файли джерел), спитай мене, а не вигадуй.»
- Ключів API не потрібно. Репозиторій публічний. Комітити по етапах. Тексти стандартів не копіювати — лише метадані.
- Банер в UI дослівно: «Демо, не юридична консультація. Клас визначає виробник; для IIa і вище його підтверджує
  нотифікований орган. Правила — чернетка, не перевірені регуляторним фахівцем».
- Спілкування з автором — українською.

## 4. M5: що вже зроблено

- **Аналізи** в `packages/core/src/analysis/`: `space.ts` (`jointInputs` — точний перебір реальних входів правила:
  ланцюг залежностей оцінюється на спільних станах із проєкцією, без надмножини), `coverage.ts`, `mcdc.ts`, `diff.ts`,
  `whatif.ts`. Визначення — DECISIONS A3.
- **CLI:** `pnpm mrn coverage`, `pnpm mrn mcdc`, `pnpm mrn whatif` (`apps/cli/src/commands/analysis.ts`).
- **Гіпотетичне правило** `data/rules/eu-mdr-classification-com-2025-1023.json` (role `hypothetical`, `revises`
  `eu-mdr-classification`, revision 2, parentRevision 1) — нове правило 11 з COM(2025) 1023, додаток I, п. (6)(g),
  дослівні цитати з `com-2025-1023-annexes/annex-i-6`; прочитання абзаців — I9, правило 13 для ПЗ без клінічної
  користі — I10 (додано секцію `mdr/annex-viii-rule-13`).
- **`data/whatif.json`**: базовий приклад когорти й умови узгодженості (`when` → `require`, з цитатами; «інформація
  для рішень» і «моніторинг» ⇒ «вихід дає клінічну користь»). Перевіряється в `pnpm mrn check` («what-if»).
- **Валідація:** ревізія мусить зберігати виходи правила, яке переглядає.
- **Знімок для web** містить попередньо пораховане `whatIf` (матриця, приклади, конфігурація).
- **UI:** перемикач «Проєкти змін» тепер активний (у даних є гіпотетичне правило). Модель екрана (`lib/view.ts`) несе
  зміни за проєктом: кроки драбини (`step.proposal`), `leaf.proposal` (вихід правила чи стан обов'язку), листки, що
  з'явилися б лише за проєктом, `branch.proposalChanges`, чипи `forProposal`, `device.proposalQuestions`. `MapView`
  їх показує (`.leaf-proposal`, `.branch-proposal`, `data-proposal` на ребрах і питаннях). Картка правила класу має
  секцію «Якби проєкт ухвалили» (`components/Proposal.tsx`): результат і «що вирішило» за проєктом (його цитати),
  змінені вимоги, матриця переходів когорти, умови узгодженості з цитатами, приклади MDCG.

Поточні результати (для README і SPEC §6):

- Покриття — чисто для всіх 6 правил: кваліфікація 2 187 входів; клас 37 260 входів (= 1 180 980 профілів з «не
  знаю»); нотифікований орган 87 (3 542 940); AI Act 684 (42 515 280); таблиця MDCG 1 488 (104 976); проєкт 16 560
  (524 880). Жодної комбінації без виходу.
- MC/DC: кваліфікація 7/7, клас 10/11, нотифікований орган 4/4, AI Act 6/6, таблиця MDCG 8/8, проєкт 10/13. Листки,
  що ніколи самі не вирішують: «3.3 з виробом класу I» (обидві версії), «несерйозна ситуація» й «інформувати» в
  проєкті (їх перекриває суворіший вихід) — це чесний результат, не баг.
- «Що як»: когорта 61 різна ситуація, клас змінюється в 29 (вищий у 13, нижчий у 16). Приклади MDCG з категоріями
  IMDRF (інсульт III, когнітивна терапія IIa, серцебиття IIb, депресія IIb, хіміотерапія IIa) клас зберігають; решта
  за проєктом — множини (настанова не дає для них ситуації й значущості).

## 5. M5: що лишилося

1. **CSS червоної ручки** (U1) у `apps/web/src/styles.css`: `.ladder-step[data-proposal]` (кільце довкола класу за
   проєктом, закреслення поточного, коли відрізняється), `.leaf-proposal`, `.branch-proposal`,
   `.ink-edge[data-proposal]`, `.node-leaf[data-proposal]`, `.branch-question[data-proposal]`,
   `.chip[data-for-proposal]`, секція `.proposal` (червона лінія ліворуч), таблиця `.matrix`, `.proposal-change`,
   `.proposal-examples`, `.constraint`. Колір — токен `--color-redpen`; світла й темна схеми. Перевірити знімками
   (`e2e/peek.ts`, див. §7).
2. **Рефакторинг:** циклічний імпорт `Card.tsx` ↔ `Proposal.tsx`. Винести `useAsk`, `QuestionList`, `SupportList`,
   `deviceName` (+ `sameProfile`) в окремий модуль (напр. `components/Questions.tsx`) і поправити імпорти в `Card`,
   `Proposal`, `MapView`, `DeviceChips`.
3. **Чекліст:** позначки проєкту (`leaf.proposal`) для результатів правил і обов'язків; секція проєкту (або та сама
   `ProposalSection`).
4. **Тести:**
   - core: `jointInputs` дорівнює грубому перебору на малому синтетичному наборі правил; `ruleCoverage` реальних правил
     без збоїв (це і є критерій M5 «кожна комбінація дає клас або явну множину»); `mcdcPairs` на синтетичних правилах
     з відомими парами; `diffRules`; `whatIf` (сума клітинок = когорта, приклади, `impliedAnswers`).
   - cli: `coverage` повертає 0; `whatif` друкує матрицю.
   - web: перемикач проєктів → драбина з позначкою, червоний рядок у листку, секція з матрицею в картці класу.
   - e2e: перемикач проєктів; `screens.e2e.ts` + знімок `08-proposal.png`.
5. **Документи:** ARCHITECTURE (модулі analysis, формат `data/whatif.json`, команди), SPEC §6 (результати вище),
   CLAUDE.md (структура `data/` + `whatif.json`).
6. Закомітити M5.

## 7. Середовище (відмінності від хмарної сесії)

- e2e шукає Chromium у `/opt/pw-browsers` (так було в хмарному контейнері). Локально задай `MRN_CHROMIUM` (шлях до
  Chrome/Chromium) або `PLAYWRIGHT_BROWSERS_PATH`; `playwright-core` 1.56.1 у `apps/web`. Чи завантажувати браузер —
  вирішує автор.
- `pdftotext` (poppler) потрібен лише для перевитягу PDF; `text.txt` закомічено, CI PDF не перевитягує.
- Мережа до EUR-Lex: бот-захист → Cellar Publications Office (див. CLAUDE.md, «Відомі пастки»).
- Швидкий перегляд екрана: `pnpm build:web && pnpm exec tsx apps/web/e2e/peek.ts <тека> 1440x900 '<хеш>'…`
  (`PEEK_DARK=1`, `PEEK_FULL=0`, `PEEK_SCALE=2`); стан екрана задається хешем URL (`apps/web/src/lib/route.ts`),
  напр. `x=heartbeat-app&b=market&s=o.route-iib&w=1` (w=1 — проєкти змін).
- `pnpm dev` — Vite з даними з `data/` через віртуальні модулі; зміна JSON у `data/` перезавантажує сторінку.
