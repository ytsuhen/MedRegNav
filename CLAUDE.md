# MedReg Navigator — інструкції для розробки

Демо для портфоліо: користувач описує медичне ПЗ (MDSW) атрибутами й бачить, чи це медвиріб, який у нього клас за MDR
(додаток VIII, правило 11), що з цього випливає за AI Act і які обов'язки, документи й стандарти потрібні. Кожна
відповідь простежується до дослівної цитати офіційного тексту. Специфікація: `docs/SPEC.md`; рішення й розбіжності з
брифом: `docs/DECISIONS.md`; модулі й формати даних: `docs/ARCHITECTURE.md`.

## Незмінні правила

- **Жодного коду, що знає конкретне правило чи статтю.** Правила, атрибути, обов'язки, стандарти, еталонні приклади —
  лише дані в `data/`. Код у `packages/` і `apps/` працює для будь-яких таких даних.
- **Кожен вузол правила і кожен обов'язок мають хоча б одну цитату з дослівного джерела** (крім структурних
  вузлів-«клею»). Цитата = sha256 нормалізованого тексту секції + зсуви + `quote`; тест перевіряє, що `quote` збігається
  з текстом за зсувами.
- **Лише дослівні тексти.** Джерела — оригінальні файли в `data/sources/<id>/` з `meta.json` (`url`, `retrievedAt`,
  `sha256`, `edition`, `notes`). Ніколи не переказувати й не відновлювати юридичний текст з пам'яті. Немає доступу до
  джерела → зупинитися й попросити файл у `data/sources/inbox/`.
- **Правила читають лише атрибути з реєстру `data/attributes.json`.**
- **Результат — підтримка рішення, а не рішення.** Усі правила мають статус `draft` і `authoredBy: "manual-reference"`.
  У UI завжди банер: «Демо, не юридична консультація. Клас визначає виробник; для IIa і вище його підтверджує
  нотифікований орган. Правила — чернетка, не перевірені регуляторним фахівцем».
- **Жодних матеріалів, назв чи кодових назв роботодавця автора. Назв комерційних рушіїв правил не згадувати.**
- **Якщо бриф суперечить дослівному тексту закону, перемагає текст закону;** розбіжність записати в `docs/DECISIONS.md`.
- Тексти стандартів (ISO, IEC) не копіювати: лише метадані (номер, редакція, для чого).
- UI українською за замовчуванням, з перемикачем EN; усі рядки — через i18n-словник. Цитати — мовою джерела (EN).
- Офлайн: жодних CDN, зовнішніх шрифтів і запитів на інше походження.

## Стек і версії (точні, `save-exact`)

TypeScript (strict, ESM), Node ≥ 22.18, pnpm 10.28 workspaces. `zod` v4 (схеми даних — єдине джерело істини),
`vitest`, `fast-check`, Biome. Web: React + Vite + Tailwind, `@xyflow/react` + `d3-hierarchy` (розклад графа без ручних
координат). Ingest: `parse5` (XHTML), `pdftotext` з poppler (PDF; лише локально, у CI витягнутий текст уже в репозиторії).
Не беремо з vlk-engine: CQL/ELM, FHIR, синтетичних пацієнтів, UCUM, пакет агента.

## Структура

```
packages/core/  чистий код без I/O (lint забороняє node:*): text/ source/ attributes/ ir/ obligations/ analysis/
apps/cli/       `pnpm mrn …`: ingest джерел, цитати, перевірка даних, оцінка профілю, аналіз, знімок даних для web
apps/web/       React SPA (статична, рушій працює в браузері); e2e/ — Playwright у передвстановленому Chromium
data/           sources/ attributes.json rules/ obligations/ standards.json examples/ navigator.json (що де на екрані)
docs/           SPEC, ARCHITECTURE, DECISIONS, screens/
```

## Команди

- `pnpm verify` — tsc, Biome, усі тести (зокрема «цитата = текст за зсувами» і еталонні приклади MDCG). Має бути
  зеленим перед кожним комітом.
- `pnpm mrn help` — CLI: `extract`, `sections`, `cite`, `quote`, `check`, `eval`, `coverage`, `mcdc`, `whatif`, `snapshot`.
- `pnpm dev` — web локально; `pnpm build:web` — статична збірка (GitHub Pages).
- `pnpm e2e` — Playwright у `/opt/pw-browsers` (браузери не завантажувати); не входить у `verify`. Скріншоти README:
  `MRN_DOCS_SCREENS=docs/screens pnpm e2e apps/web/e2e/screens.e2e.ts`.
- `pnpm format` — Biome з автовиправленнями.

## Відомі пастки

- EUR-Lex відповідає не-браузерним клієнтам `202` з порожнім тілом (захист від ботів). Ті самі офіційні документи
  віддає Cellar Publications Office: `https://publications.europa.eu/resource/celex/<CELEX>` з `Accept: text/html` і
  `Accept-Language: eng` → `303` на `http://…/DOC_1`; редирект переписати на `https://`. Пошук версій — SPARQL
  `https://publications.europa.eu/webapi/rdf/sparql` (`cdm:resource_legal_id_celex`).
- `health.ec.europa.eu` інколи відповідає `429` → повторити через паузу.
- Консолідований текст містить маркери змін (`►M1`, `◄`, `▼B`): екстрактор їх прибирає (D-рішення в DECISIONS).
- `pdftotext` інших версій дає інший текст → `text.txt` комітимо, його sha256 — у `meta.json`; CI PDF не перевитягує.
- React Flow пропускає клік крізь вузол, який не можна виділити чи перетягнути: вузлам з кнопками —
  `style.pointerEvents = "all"` (U10). happy-dom цього не бачить, тож кліки по мапі перевіряє e2e.
- UI не знає id правил: що показати у вузлі пристрою й на гілках, задає `data/navigator.json` (U4).
